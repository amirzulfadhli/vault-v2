# Security Policy 

## Supported versions 

Vault V2 is an actively developed experimental project. Security fixes are 
primarily applied to the current development version. 

## Reporting a vulnerability 

Please do not publicly disclose security vulnerabilities through GitHub 
issues. 

Security vulnerabilities should be reported privately to the project 
maintainer through the security contact or private reporting mechanism 
provided by the repository. 

Please include: 

- A description of the vulnerability.
- Steps to reproduce it.
- The affected component or version.
- The potential impact.
- Suggested mitigation, if known.

Do not include real secrets, private notes, credentials, or personal data in 
the report. 

## Security areas 

Security review is particularly relevant to: 

- Markdown and structured metadata processing.
- Static-site generation and publishing.
- AI-assisted content processing.
- Automation workflows.
- Dependency security.
- File-system access.
- Input validation.
- Injection vulnerabilities.
- Secrets and API credentials.
- Accidental publication of private content.

## Private information 

Vault V2 may process personal knowledge and other information that should not 
be publicly exposed.

Users are responsible for ensuring that private content is excluded from 
public repositories and publishing workflows.

## Responsible disclosure 

Please provide reasonable time for the maintainer to investigate and address 
a vulnerability before publicly disclosing technical details.
