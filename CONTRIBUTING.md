# Contributing to Vault V2 

Thank you for your interest in contributing to Vault V2. 

Vault V2 is an experimental knowledge-management system and digital garden
built around Markdown, structured categorization, Obsidian-compatible notes, 
static publishing, and AI-assisted knowledge processing. 

The project is still evolving, so contributions that improve reliability, 
documentation, tooling, organization, and developer experience are welcome. 

## Before contributing 

Please: 

1. Read the README.
2. Check existing issues and pull requests.
3. Keep changes focused.
4. Explain the motivation behind significant changes.
5. Never commit private notes, credentials, API keys, or personal information.

## Content and privacy

Vault V2 may be used with personal knowledge and Markdown content. 

Contributors must ensure that they do not submit private, confidential, or 
personally sensitive material without authorization. 

Do not include: 

- API keys.
- Passwords.
- Access tokens.
- Private notes.
- Personal credentials.
- Private datasets.
- Other sensitive information.

## Pull requests 

Pull requests should: 

- Clearly describe the change.
- Explain why it is useful.
- Include relevant tests or validation where appropriate.
- Avoid unrelated changes.
- Update documentation when behavior or project structure changes.

Changes to the knowledge structure, publishing pipeline, or automation should 
include enough context for maintainers to understand their effects. 

## Issues 

Bug reports should include: 

- What happened. - Expected behavior.
- Steps to reproduce the problem.
- Relevant environment information.
- Logs or examples with private information removed.

For security vulnerabilities, follow `SECURITY.md` instead of opening a 
public issue.
